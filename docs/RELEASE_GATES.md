# SENTINEL RC1 Release Gates

The exact commit being released must have evidence for every required automated gate. Missing evidence is not a pass.

## Required

1. Core compile and unit/API/security tests pass.
2. Core coverage is at least 80%.
3. Android debug APK builds and JVM tests pass without release-signing secrets.
4. Web lint and production build pass.
5. Container build passes.
6. CodeQL passes for Python and JavaScript.
7. Dependency audit and Trivy filesystem scan pass with no unfixed HIGH/CRITICAL findings.
8. Database migrations apply cleanly from an empty PostgreSQL database.
9. Enrollment, device proof, refresh rotation, replay and authorization regression tests pass.
10. Release artifacts are generated by the release workflow.

## Environment-level gates

Before production traffic, additionally verify:

- TLS certificate and HSTS behavior at the real ingress.
- GitHub Secret Scanning and push protection are enabled.
- Production enrollment secret and database credentials are injected externally.
- WAF/API-gateway rate limiting is enabled if more than one Core replica is used.
- Backup and restore procedure has been exercised against the target PostgreSQL service.
- OWASP ZAP/Burp or equivalent runtime penetration testing is completed for the deployed endpoint.

## Release command

After the exact commit is green:

```bash
git tag -a v1.0.0-rc1 -m "SENTINEL 1.0.0-RC1"
git push origin v1.0.0-rc1
```

The release workflow creates the GitHub release and attaches the Android debug artifact and Core source bundle.
